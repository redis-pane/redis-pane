---
title: "Dashboard"
---

`g d` opens the Dashboard: the server's own vitals, from `INFO`, refreshed every two seconds
while the view is open. `Esc` or `g k` returns to the keys, exactly as you left them.

<Demo name="dashboard" alt="The Dashboard: six tiles updating while another client writes, then one tile expanded into its raw INFO section" />

| Tile | Shows |
| --- | --- |
| Memory | Used memory against `maxmemory` as a bar, and the peak. With no `maxmemory` it reads "no limit". |
| Hit ratio | Hits against misses. |
| Ops/sec | The current rate and a sparkline of the last two minutes. |
| Clients | Connected and blocked clients, and rejected connections. |
| Replication | Role and lag. |
| Evictions | Evicted and expired keys. |

Anything alarming is coloured and also marked with a glyph or word, so you don't need colour to
see it. The thresholds are fixed:

- Memory warns at 80% of `maxmemory` and is critical at 95%.
- Hit ratio warns below 80%, but only once there have been 1,000 reads, so a fresh server doesn't
  raise a false alarm.
- Replication lag warns above 5 seconds, and is critical above 30 or when the link is down.
- Any blocked client warns. Evictions that are rising warn. Rising rejected connections are
  critical.

## Keys

| Key | Does |
| --- | --- |
| `←` `→` `↑` `↓` or `h` `j` `k` `l` | Move between tiles. |
| `⏎` | Expand the tile into the raw `INFO` section behind it. |
| `c` | Copy that section. |
| `r` | Poll now. |

`Esc` closes the expanded section first, then leaves the view.

The grid shows three tiles across at 120 columns and wider, two at 80 to 119, and one below that,
scrolling.

## On a Cluster

`INFO` is per node, so on a Cluster the Dashboard asks every node, each on its own connection, so
that one dead node doesn't stall the view.

- A health line reads, for example, `cluster_state ok · 16384/16384 slots · 0 failing`. It turns
  alarming if the state isn't `ok` or any slot is unassigned or failing.
- The tiles are totals over the Cluster: memory is summed over the primaries, the hit ratio is
  computed from summed hits and misses, and replication shows the worst lag.
- A **node table** lists every node, primaries first, with its role, slots, memory and so on. A
  node that didn't answer keeps its row and says `INFO failed`.
- `↑` `↓` or `j` `k` move along the table and `⏎` opens one node's own tiles. `Esc` goes back to
  the overview, and then leaves the view.
